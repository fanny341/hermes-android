# Moritzu Hermes — APK Size & Performance Optimization Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Reduce debug APK size from 152 MB to under 80 MB and eliminate UI jank during chat streaming.

**Architecture:** The app is a Flutter chat client for the Hermes AI agent. The 152 MB debug APK is caused by no ProGuard/R8 minification, multi-arch native libraries, and disabled icon tree-shaking. The lag comes from calling `setState` on every SSE token, which triggers a full `ListView.builder` rebuild of all messages.

**Tech Stack:** Flutter 3.44.8, Dart 3.12, Android SDK 36, GitHub Actions CI

## Task 2: Add ABI split config to build.gradle.kts

**Objective:** Split the APK per architecture so each APK only contains native libs for ONE arch, dramatically reducing per-device size. The app only targets arm64-v8a (modern Android phones).

**Files:**
- Modify: `android/app/build.gradle.kts`

**Step 1: Add `splits` block inside `android { }`**

Add after `buildTypes { }`:

```kotlin
splits {
    abi {
        enable true
        reset()
        include "arm64-v8a"
        universalApk false
    }
}
```

This creates a single APK containing only arm64-v8a native libraries (~30 MB smaller).

**Step 2: Update CI upload to use the split APK path**

Change upload path in `.github/workflows/build-apk.yml` from:
```
build/app/outputs/flutter-apk/app-debug.apk
```
To:
```
build/app/outputs/flutter-apk/app-arm64-v8a-debug.apk
```

**Step 3: Verify**

Run `flutter build apk --debug` locally (or via CI), confirm APK size is significantly smaller (should drop from ~152 MB to ~50-60 MB).

**Step 4: Commit**

## Task 4: Optimize chat_screen.dart — debounce setState

**Objective:** Replace per-token `setState` with batched updates to reduce UI rebuilds from 24+ times to ~4-6 times per response.

**Files:**
- Modify: `lib/core/screens/chat_screen.dart`

**The problem:** `_sendMessage` calls `setState` inside `onToken` for EVERY token (line 382). Since `_buildBody` iterates ALL messages and `ListView.builder` rebuilds the visible items, this causes O(n) work per token.

**Step 1: Add a token buffer**

Add a `_tokenBuffer` field:
```dart
final StringBuffer _tokenBuffer = StringBuffer();
```

**Step 2: Accumulate tokens, then batch-setState every 100ms**

Instead of:
```dart
onToken: (token) {
  if (!mounted) return;
  setState(() {
    _thinking = false;
    if (_messages.isNotEmpty && _messages.last['role'] == 'assistant') {
      _messages.last['content'] =
          (_messages.last['content'] as String) + token;
    }
  });
},
```

Use a timer-driven flush:
```dart
Timer? _flushTimer;

onToken: (token) {
  if (!mounted) return;
  _tokenBuffer.write(token);
  _flushTimer ??= Timer(const Duration(milliseconds: 100), () {
    if (!mounted) return;
    final chunk = _tokenBuffer.toString();
    _tokenBuffer.clear();
    _flushTimer = null;
    setState(() {
      _thinking = false;
      if (_messages.isNotEmpty && _messages.last['role'] == 'assistant') {
        _messages.last['content'] =
            (_messages.last['content'] as String) + chunk;
      }
    });
  });
},
```

Also flush the buffer in `onDone`:
```dart
onDone: () async {
  _flushTimer?.cancel();
  _flushTimer = null;
  if (_tokenBuffer.isNotEmpty) {
    final chunk = _tokenBuffer.toString();
    _tokenBuffer.clear();
    setState(() { ... });
  }
  ...
},
```

**Step 3: Verify**

Run `flutter analyze lib/core/screens/chat_screen.dart` — 0 errors.
Test on device — scrolling should feel smoother during streaming.

**Step 4: Commit**

```bash
git add lib/core/screens/chat_screen.dart
git commit -m "perf: batch setState per 100ms in chat streaming"
```

## Risks & Tradeoffs

1. **ABI split** — Only arm64-v8a APK means users on older 32-bit phones (armeabi-v7a) can't install. Fine for modern devices.
2. **Token buffering** — 100ms delay means slightly less "live" feel. Can tune down to 50ms if too noticeable.
3. **ProGuard** — May break plugin code. Test thoroughly before releasing. Safe to skip for debug builds.
4. **Dead code removal** — Removing a package that IS used will break the build. Verify on CI.
